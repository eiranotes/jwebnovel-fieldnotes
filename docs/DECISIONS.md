# Decisions Log

## 2026-09-06

### D-001: 외부 다운로더를 subprocess로 고정하지 않음

다운로더 프로젝트 하나에 전체 파이프라인을 종속시키면 사이트 변경, 출력 포맷 변경, 번역 상태 관리가 서로 얽힙니다. 따라서 검색/다운로드/번역/보고서를 별도 모듈로 둡니다.

### D-002: SQLite + 작품별 파일을 병행

SQLite는 dedupe/실행 이력/청크 상태 조회용, 파일은 사람이 직접 검수하고 재가공하기 위한 원문/번역 산출물용입니다.

### D-003: 첫 5화는 회차별 원문을 먼저 저장 후 병합

단일 파일만 보존하면 중간 회차 재수집과 변경 감지가 어렵습니다. `raw/001.txt` 같은 회차 파일을 source-of-truth로 두고 병합 파일은 재생성 가능한 산출물로 취급합니다.

### D-004: 루비는 `표기《읽기》` 형태로 보존

일본어 인명/고유명사 번역 시 루비가 직접적인 발음 힌트가 되므로 제거하지 않습니다. 별도의 `glossary.json`에도 ruby pair를 seed로 추가합니다.

### D-005: 번역 API 키는 환경변수만 사용

API 키가 config, SQLite, 로그, 작품 폴더에 기록되지 않도록 합니다.

### D-006: GPL 참고 구현은 clean-room 설계만 반영

`ripdog/tsundoku`의 상태/고유명사 유지 개념은 참고하되 GPL 소스는 복사하지 않습니다.

### D-007: 실제 스케줄 설치는 검색 조건 확정 후 수행

파이프라인 자체와 launchd installer는 제공하지만, 조건이 비어 있는 상태에서 빈 작업을 매일 등록하지 않습니다.
