# Daily ChatGPT/Steroids Job Contract

You are executing the daily Japanese web-novel research pipeline in repository:
`/Volumes/DevDrive/Projects/fieldnotes`.

Use Chat On Steroids Core for all repository reads/writes, state mutation, git operations and validation. Use current web search for discovery. Body acquisition is performed only by the repository's private local acquisition routes; never publish source or translated fulltext to GitHub Pages.

For this run:

1. Import phone/private-console state first with `python3 scripts/runtime_sync.py pull`. The runtime mirror is not a Git repository; the canonical repository remains `/Volumes/DevDrive/Projects/fieldnotes`.
2. Start a run log with `python3 scripts/automation_log.py --task daily_discovery --action run --status started ...` and keep the same run id for the daily discovery steps.
3. Read `config/automation.json`, `config/search-profiles.json`, `docs/search-protocol.md`, `docs/canonical-pipeline.md`, `data/automation-status.json`, and rebuild the persistent seen index with `python3 scripts/rebuild_work_index.py`. Seed/read the verified discovery lessons with `python3 scripts/learning_store.py seed` and `python3 scripts/learning_store.py context --domain discovery`. Read `docs/preference-learning.md` v2. Keep discovery, request fingerprinting, base scoring and candidate feature extraction blind to learned weights. The ranker loads/rebuilds the private model later; do not use `--include-preferences` for discovery.
4. Select the search groups for this run with `python3 scripts/select_search_profiles.py --commit`. If the page explicitly selected more than one group, run every selected group separately. If none is selected, obey `selection.when_none` (`round_robin`, `least_recently_run`, `random_daily`, or `all_enabled`) and `rotation_batch_size`.
5. If no enabled profile is available, update status/logs, run `python3 scripts/runtime_sync.py push`, and stop without inventing criteria.
6. For each selected profile create a draft using `new_entry.py --profile PROFILE --date DATE --title TITLE`. Prepare the analyzed request contract described in `docs/preference-learning.md`, with all explicit/fingerprint dimensions, and freeze it using `new_entry.py --freeze-request ENTRY --request REQUEST.json` BEFORE discovery. Use a new entry if the frozen request changes.
7. Discover fresh candidates with current web/platform metadata. Apply that profile's constraints and default 300,000-char threshold. Keep sub-300k only as explicit high-fit length exceptions. Apply active discovery operational lessons only where their guard matches the current request. Score base relevance from the frozen current request only. Do not introduce accumulated taste into harvesting filters or base_score.
8. Before sampling/ranking, compare the harvested candidate list against `data/work-index.json` or batch it through `python3 scripts/work_index.py --unseen-only`. In strict mode, do not re-surface works already present in the index. Cross-posts are canonicalized by normalized title + author when available.
9. Acquire pre-ranking accessible body samples privately for qualified candidates, not only the final shortlist. Generate core request-neutral features as well as newly observed dimensions; do not restrict vocabulary to learned atoms. Supply the v2 candidate contract: explicit 0–100 `base_score`, request-bound eligibility receipt, hashed private sample paths, and unique features with exact source spans. Run `python3 scripts/preference_rank.py --profile PROFILE --context ENTRY --request REQUEST.json --input CANDIDATES.json --count N --seed DATE:PROFILE:ENTRY`. Missing request/sample proof or a missing work index is a blocker. The implicit minimum is 300,000 characters; an authorized default-length exception records min_chars=fail plus sourced length_exception_fit=pass, never a false min_chars=pass. Draft/request profile IDs must match. The ranker saves create-only private traces and reserves explore within the review budget. Do not copy private weights/features into public artifacts.

10. Run `python3 scripts/new_entry.py --finalize ENTRY`. Generate archive HTML/Markdown/index from that finalized JSON. Never rewrite its selected slate or frozen request. Preserve source-backed harvest/rejection summaries without private learned weights; retain all candidate/probability evidence in the private trace. Rebuild `data/work-index.json` and record verified operational lessons. Schema-2 validation and target registration reject missing or inconsistent traces.

11. Run `scripts/full_pipeline.py --entry ENTRY_ID --top-n N --episodes 5`. It registers targets, acquires the first five public reader episodes into the private local workspace, prepares merged source, creates the resumable chunk queue, seeds ruby/glossary evidence, and updates status. Reuse existing acquisition manifests unless a refresh is needed.
12. If automatic acquisition fails for a work, retain the manual `source_inbox/` fallback and record the blocker instead of discarding the candidate.
13. Seed/read verified translation lessons with `python3 scripts/learning_store.py seed` and `python3 scripts/learning_store.py context --domain translation`. For a production multi-work run use `python3 scripts/translate_parallel.py --entry ENTRY_ID --workers 2 --launch-gap 30`; it invokes `translate_project.py` for one sequential chunk per work at a time. Never run more than two distinct browser-backed works concurrently and never manually translate/complete a queue task outside the driver.
14. Primary translation uses one exact ChatGPT Project conversation per `(work_id, role)`, Project-source proof in the same translation result, one exact local task read, strict sentence/glossary validation, and transactional completion. The driver is fail-closed across both model lanes. Configured fallback is `codex_webgpt`; it is permitted only for the explicit `fallback.trigger_codes` in `config/project-translation.json`. `WORKER_RESULT_TIMEOUT`, uncertain submission/transport, source/hash changes, and commit uncertainty must stop without fallback or resubmission.
15. Continue only up to the configured daily translation cap. A local bridge `rate_limited` error is retried as local pre-route throttling; provider rate limits stop new launches. Already accepted operations are resumed/polled rather than submitted again. Record new recurring translation failures as observed operational lessons and promote fixes only after regression/E2E verification.
16. Run `scripts/refresh_automation_status.py`, `scripts/rebuild_work_index.py`, and `scripts/validate_repo.py`.
17. Finish the run log with done/partial/error status. Commit only public metadata/docs/code/state, never source or translated fulltext. Push main and verify GitHub Pages responds successfully.
18. The private `taste.html` daily review deck is derived only from that date's `shortlist` and `length_exceptions`. Merge v2 shortlist/length_exceptions by preference_rank (selected_candidates), including for top-N acquisition. Do not include rejected/deprioritized works. It uses the local acquired sample so the user can read and answer from iPhone without publishing source text.
19. Refresh the internal private runtime with `python3 scripts/runtime_sync.py push` so the iPhone daily taste page and operations console see the newest entries, local samples, profile state, queues, artifacts, feedback model and logs.
20. Run `python3 scripts/preference_evaluate.py` to report qualified/selected/reviewed/explore coverage; do not call observed ratings unbiased search quality. Independent user-labeled recall benchmarks and future prospective contexts remain necessary. Report: selected search groups, new entries, duplicates filtered, shortlist count, daily taste deck count, full-translation progress, translated chunks, active/new learning lessons, blockers.
